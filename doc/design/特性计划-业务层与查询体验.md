# 特性计划：业务层与查询体验

> **读者**：mooSQL 维护者 / 架构设计  
> **目标**：在保持 SQL-first 的前提下，补齐业务更新、缓存、厚仓储与查询表面体验。  
> **原则**：以扩展层 / 可选包 / Repo·Clip 增强接入，不替换内核；**业务厚 API 只进富仓储**。  
> **实施文档**：`doc/design/plan/业务层与查询体验-实施文档.md`（含落点边界 §0.1）。

关联：`doc/slave/与主流ORM功能对比.md`、`doc/docs/SQL/high/repository.md`、`doc/shard/`

---

## 1. 不可妥协的边界

| 原则 | 含义 |
|------|------|
| SQL-first | `SQLBuilder` / 步骤编排仍是一等公民 |
| 多入口 | `useSQL` / `useClip` / `useRepo` / Fast·Ext LINQ 共存 |
| Pure / Ext 拆分 | 核心不绑死驱动；方言可插拔 |
| 主从与多库 | cluster / 健康 / Failover 路线继续投入 |
| 浅抽象 | 不为「厚业务层」牺牲 SQL 可见性 |
| **厚能力不回灌薄仓** | Tracking / EntityCache / SchemaEnsure / UpsertOptions **只**在 `SooRichRepo`；**不**扩展到 `SooRepository` / 更下层 |
| **SQL 特性与业务 API 分离** | CASE / Window / SELECT `setCache` 属 SQL/查询特性，落 Builder；与富仓储字典缓存等无关 |

已有壁垒（只增强、不替代）：SQLBuilder / CTE / MERGE / SQLApart、主从高可用、Ext LINQ、`IEntityAnalyser`、AuthBuilder、AOT Generator、多 TFM 与基准测试。

### 1.1 新 API 落点（摘要）

| 类型 | 示例 | 落点 |
|------|------|------|
| SQL / 查询特性 | `caseWhen` / `window` / `setCache` | `SQLBuilder` 优先；CASE/Window 可由 Clip 借用 |
| 业务厚能力 | 脏追踪、EntityCache、EnsureSchema、InsertOrUpdate(options) | **仅** `useRichRepo` / `SooRichRepo` |
| 薄仓储 | 既有 CRUD | `useRepo` / `SooRepository` **保持不变** |

## 2. 现状缺口（简表）

| 能力 | 现状 | 计划方向 |
|------|------|----------|
| 薄仓储 CRUD | ✅ `SooRepository` | 保持 |
| 厚业务仓储 | 🟡 偏薄 | `useRichRepo` / `SooRichRepo` |
| 脏字段更新 | ❌ | EntitySnapshot + Dirty Update |
| 实体字典缓存 | 🟡 有结果缓存 | EntityCache + RichRepo |
| 查询 Expire 统一 | 🟡 Builder 有钩子 | Clip/Repo/LINQ 链上统一 |
| Upsert 选项对象 | 🟡 有 MERGE SQL | `UpsertOptions` 绑定 **富仓储** |
| CASE / Window API | 🟡 分散 | SQLBuilder 一等 → Clip 借用 |
| Include 关联加载 | 🟡 有 SQLBuilder nav；缺 Repo/Clip 一等 `Include` | 见 `navigation.md`；规划 `Include` / `loadWith` |
| 业务事务包装 | 🟡 有 UoW | `useTrans` 糖 |
| Schema 一键同步 UX | 🟡 有 DDL | `EnsureSchema`（P0，`richRepo/schema`） |
| 分片实体定位注册 | 🟡 有 interceptor | `configureShardFor<T>` |
| CompileToSp | ❌ | P2 可选扩展包 |

## 3. 特性清单（按优先级）

### P0 — 优先

#### 3.1 脏字段更新（Change Tracking）

**收益**：减少无谓列更新；与 `EntityTranslator` 契合；最终仍落到 `SQLBuilder.update().set(...)`。

**落点（仅富仓储）**

| 组件 | 做法 |
|------|------|
| 快照 | `EntitySnapshot` / `ITrackedEntity`，优先原始值快照（避免 hash 碰撞） |
| 富仓储 | `SooRichRepo.Update` 已追踪则脏列；`UpdateAllColumns` 全量逃生 |
| 便捷 API | `db.useRichRepo<T>().UpdateDirty(entity)` / `autoTrackOnQuery()` |
| 薄仓 | **不**增加 Tracking API；`useRepo.Update` 语义不变 |

**约束**：BLOB/JSON 等大列可排除；批量更新走显式 set；**禁止**把 Tracking 下沉到 `SooRepository`。

#### 3.2 业务厚仓储（可选层）

**收益**：字典/配置收口；传统分层项目更好落位；**本计划全部业务厚 API 的唯一对外入口**。

```text
SooRichRepo<T>                 ← 独立类型（组合 SooRepository 转发 CRUD）
  + Track / UpdateDirty / UpdateAllColumns / autoTrackOnQuery
  + AllCache / QueryFromCache / ClearCache
  + EnsureSchema() / PreviewSchema() / SyncFields() / SyncCaptions()
  + InsertOrUpdate(..., UpsertOptions)
  + Thin 属性访问内部薄仓
  + DBInstance.useRichRepo<T>() 创建
```

- 不强制继承；默认仍用 `useRepo`  
- 代码目录：`pure/src/adoext/richRepo/`（Schema 在 `richRepo/schema/`）  
- **不**把上述成员复制到 `SooRepository`

#### 3.3 查询链统一缓存语义（SQL / 结果缓存特性）

- SELECT 结果缓存：`SQLBuilder.setCache(key|ttl)`（**不**提供 Clip `.expire`）  
- 与 `ISooCache`、SQLBuilder 缓存打通，一套 key 规则  
- 文档区分：**结果缓存**（Builder `setCache`） vs **实体字典缓存**（仅 RichRepo）  
- 结果缓存 **不是** 富仓储能力，**不得**与 `AllCache` 混为一谈

#### 3.4 富仓储 UpsertOptions

- 复用现有 MERGE / 方言 upsert  
- `SooRichRepo.InsertOrUpdate(entity, options)` + 批量切片  
- **不**在 `SooRepository` 上增加同名 API  
- 选项：约束列、存在则跳过、更新列白名单、`BatchSize`  
- 方言：MSSQL/Oracle/PG/Oscar/DM MERGE、MySQL ON DUPLICATE；否则先查后写

#### 3.5 Schema 一键对齐（EnsureSchema）

- 代码：`pure/src/adoext/richRepo/schema/`  
- **主入口**：`useRichRepo<T>().EnsureSchema(SyncMode)` / `PreviewSchema` / `SyncCaptions`  
- `db.useDDL().ensure<T>(...)` 糖（门面，不表示薄仓具备 Schema UX）  
- 复用 `DDLBuilder.doInitTable`；**默认只增不删**  
- 危险模式 `AddAndDropExtraColumns` 须 `AllowDropColumn` 双闸；生产可关 `AllowSchemaSync`  
- 对标 CRL：`CreateTable` / `SyncTableFields`（改造其默认 DROP）/ `UpdateTableFiledComments`

---

### P1 — 其次

#### 3.6 CASE / 窗口函数一等 API

- Clip / Fast LINQ：`caseWhen` / `over().partitionBy().orderBy()`  
- 落到 SQLBuilder 表达式与方言函数  
- 复杂场景仍可用 `useSQL`

#### 3.7 Include / 关联加载

- **现状（SQLBuilder 导航）**：`includeHis` / `includeNav` / `useNavSave` 与 `NavQueryGuide` / `NavGuideSave` 已落地（二次 `IN` 查询回填、分层 UoW 保存）。说明见 `doc/docs/SQL/high/navigation.md`。
- **规划增强（Repo / Clip / 查询链 DX）**：`Include(x => x.Orders)` 或 `loadWith` 一等入口；默认拆查询（可控 1+N）；禁止隐式笛卡尔爆炸  
- 跨分片 Include 默认禁用并写清边界
- 与 Fast/Ext LINQ 的 `Includes` 并行，不互相替代

#### 3.8 业务事务糖

```csharp
db.useTrans(work =>
{
    work.useRepo<User>().Update(...);
    work.useRepo<Order>().Insert(...);
    return true; // false → 回滚
});
```

- 内部：`LiveTransaction` / UoW  
- 支持 `Result` / `out error` 风格  
- 跨库不假装同一事务

#### 3.9 实体级分片注册

- `configureShardFor<T>(entity => key)`（命名按项目惯例）  
- Repo 写入自动带 shard key  
- 内核仍用现有 interceptor / `useShard`

### P2 — 可选 / 不做

| 项 | 决策 | 说明 |
|----|------|------|
| CompileToSp | 扩展包试点 | 运维成本高，不进默认路径 |
| 字段名混淆 | ❌ | 与 database-first、可观测 SQL 冲突 |
| Remoting / ApiProxy | ❌ 不进 Pure/Ext | 属应用基础设施 |
| 强制实体基类（Id/AddTime） | ❌ | 保持多分析器、可选约定 |
| 用厚仓储替换 SQLBuilder | ❌ | — |
| 弱化 Ext LINQ | ❌ | — |
| Tracking / EntityCache / Schema / Upsert 下沉薄仓 | ❌ | **只进** `SooRichRepo`；见 §1.1 |

## 4. 路线图

### 阶段 A — 更新、缓存与 Schema（1～2 迭代）

1. Dirty Update（快照 + **仅富仓储**脏字段路径）  
2. 统一缓存门面：SQLBuilder `setCache`（ResultCache）+ RichRepo 对象缓存（EntityCache）— **二者分离**  
3. UpsertOptions（**仅** `SooRichRepo`）  
4. EnsureSchema（`richRepo/schema`；安全默认不 DROP）  
5. `SooRichRepo` + `useRichRepo` 作为厚 API 唯一入口  

**验收**：富仓储局部更新 SQL 可预期；薄仓行为不变；字典缓存可用；EnsureSchema 默认只增不删；基准无回退。

### 阶段 B — 查询表面（2～3 迭代）

1. CASE / Window 链式 API（**SQLBuilder 先**，Clip 借用）  
2. Include / loadWith  
3. 联表投影文档与示例（业务 DTO）  
4. Clip 路径全覆盖 `PrintQuery` / 慢 SQL / `MooEvents`  

**验收**：常见后台列表（筛选+分页+联表投影）多数无需手写 SQL。

### 阶段 C — 业务亲和层（并行 / 随后）

1. `useTrans`  
2. 实体级分片注册  
3. 专题文档《业务仓储与缓存指南》（写清：厚 API 只进 RichRepo）  

**验收**：薄/厚仓储双路径示例可跑通；文档无「useRepo 脏更新/EnsureSchema」误导。

### 阶段 D — 明确外置

CompileToSp 仅扩展包；Remoting、字段混淆、替换 SQLBuilder 均不纳入内核。

## 5. 落地形态

```text
应用
  ├─ useSQL / useClip / useQueryable     ← SQL / 查询特性（CASE、Window、setCache…）
  ├─ useRepo<T>                          ← 薄仓储（CRUD；不挂厚 API）
  ├─ useRichRepo<T>                       ← 厚业务层唯一落点（可选）
  └─ useTrans / useWork                  ← 事务糖 + UoW

内核
  SQLBuilder → Dialect → DBExecutor      ← 不动哲学

横切（类型可在 richRepo；对外 API 只挂 RichRepo）
  Tracking · EntityCache · UpsertOptions · SchemaEnsure
```

| 能力 | 归属 | 对外入口 |
|------|------|----------|
| Dirty Tracking / UpsertOptions / EntityCache / SchemaEnsure | Pure（`adoext/richRepo`） | **仅** `useRichRepo` |
| CASE / Window / `setCache` | Builder → Clip 借用 CASE/Window；缓存仅 Builder | `useSQL` / `useClip` |
| 薄仓 CRUD | `adoext/repository` | `useRepo`（不变） |
| CompileToSp | Ext 可选模块 | — |

## 6. 目标 API 草图

```csharp
// —— 业务厚能力：一律 useRichRepo ——
var users = db.useRichRepo<User>().autoTrackOnQuery();
var user = users.GetById(1);
user.Email = "n@x.com";
users.Update(user);              // 仅 Email
users.UpdateAllColumns(user);    // 全量

var dict = db.useRichRepo<SysDict>();
var name = dict.QueryFromCache(x => x.Code == "A").FirstOrDefault()?.Name;
dict.ClearCache();
dict.EnsureSchema(SyncMode.AddMissingColumns);
dict.PreviewSchema();
db.useDDL().ensure<User>(SyncMode.AddMissingColumns); // 门面糖

db.useRichRepo<User>().InsertOrUpdate(user, new UpsertOptions
{
    ConstraintMembers = { nameof(User.UserName) },
    UpdateMembers = { nameof(User.Email), nameof(User.Status) },
    IfExistsSkipUpdate = false,
    BatchSize = 500
});

// —— SQL / 查询特性：Builder（非富仓储；不提供 Clip .expire）——
var list = db.useSQL()
    .setTable("User")
    .where("Status", 1)
    .setCache(TimeSpan.FromMinutes(5))
    .queryList<User>();

// —— 薄仓：行为不变 ——
db.useRepo<User>().Update(user);

// 事务糖
db.useTrans(work =>
{
    work.useRichRepo<User>().Update(user);
    work.useRepo<Order>().Insert(...);
    return true;
});
```

命名可按既有 `useXxx` 惯例微调；入口保持在 `DBInstance`。

## 7. 风险

1. **厚仓储必须可选**，默认路径仍是 SQL/Clip/`useRepo`。  
2. **禁止厚 API 回灌薄仓**，避免双路径语义分裂。  
3. **缓存一致性**：写路径失效钩子；主从延迟写入文档；ResultCache ≠ EntityCache。  
4. **Tracking 成本**：大列可排除；批量走显式 set。  
5. **Include 性能**：限制深度/条数；分片默认关跨片 Include。  
6. **Schema DROP**：默认禁止；危险模式双闸；生产关 `AllowSchemaSync`。  
7. **基准绑定**：每层糖用 `Tests/TestFast` 回归，尤其 Ext LINQ。

## 8. Roadmap 一览

| 优先级 | 项 | 预期收益 | 依赖 / 入口 |
|:------:|----|----------|-------------|
| P0 | Dirty Update | 更新 SQL 更干净 | EntityTranslator；**仅 RichRepo** |
| P0 | EntityCache + RichRepo | 字典/配置 DX | ISooCache；**仅 RichRepo** |
| P0 | SQLBuilder `setCache` | 结果缓存心智统一 | 现有 cache；仅 Builder |
| P0 | UpsertOptions | 少写 MERGE 样板 | 方言 upsert；**仅 RichRepo** |
| P0 | EnsureSchema UX | 开发期表结构对齐 | DDLBuilder + `richRepo/schema` |
| P1 | CASE / Window API | 分析查询少写 SQL | SQLBuilder → Clip |
| P1 | Include / loadWith | 联表读取 DX（在现有 nav 之上） | Repo/Clip + `navigation.md` |
| P1 | `useTrans` | 降低事务样板 | LiveTransaction |
| P1 | 实体级分片注册 | 与写入闭环 | shard |
| P2 | CompileToSp 扩展包 | 特定 MSSQL 项目 | 可选 |

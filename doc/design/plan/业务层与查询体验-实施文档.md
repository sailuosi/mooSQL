## 2. CRL → mooSQL 映射（采纳 / 改造）

| CRL | mooSQL 落点 | 决策 |
|-----|-------------|------|
| `IModel.Changes` + `Change()` / `Cumulation()` | `EntityChangeBag`（可选）+ 扩展方法 | **采纳**手动标记；不强制继承 |
| `ModelTracking`（hash 快照） | `EntitySnapshot`（**原始值**快照） | **改造**：不用 `GetHashCode`，避免碰撞 |
| 无 Changes 则全列更新 | `Update` 默认脏列；`UpdateAllColumns` 逃生 | **改造**：默认行为更安全、文档明确 |
| `ProviderOrigin` / `BaseProvider` | `SooRepository` + `SooRichRepo` | **分层**：薄/厚双路径，厚可选 |
| `AllCache` / `QueryFromCache` / `CacheQuery` | RichRepo 实体字典缓存 | **采纳**语义 |
| `Expire(minutes)` 查询缓存 | `.expire(TimeSpan)` / `.useCache` | **采纳**；统一 key 规则 |
| `InsertOrUpdateOption` | `UpsertOptions` | **采纳**并跨方言 |
| `PackageTrans` | `db.useTrans(...)` | **采纳**糖；同库 |
| `CreateCase` / `CreateWindowFunc` | Clip `caseWhen` / `over()` | **采纳**链式；参数化优于字面量拼接 |
| `Include` + Relation | Repo/Clip `Include` → 现有 nav | **复用** `NavQueryGuide`，不重造 |
| `SyncTableFields`（可 DROP） | `EnsureSchema(SyncMode)` + 双闸 | **改造**：默认只增不删；见 §4.6 |

## 3. P0-1 对象修改追踪（Dirty Tracking）— 详细实现

### 3.1 设计目标

1. `Update(entity)` 只 `SET` 变更列（+ PK WHERE）。  
2. POCO 友好：不强制实体基类、不做动态代理。  
3. 提供三条路径（按推荐顺序）：  
   - **A. 快照追踪**（主推，查询后自动或显式开始）  
   - **B. 手动标记**（`MarkDirty` / `Change`，对标 CRL `Change`）  
   - **C. 全量逃生**（`UpdateAllColumns`）  
4. 最终仍落到 `SQLBuilder.update().set(...).where(...)` / `EntityTranslator`。

### 3.2 类型与文件布局

**代码根目录**：`pure/src/adoext/richRepo/`

```text
pure/src/adoext/richRepo/
  tracking/
    ITrackedEntity.cs          # 可选接口（不强制实现）
    EntityChangeBag.cs        # 手动脏字段袋（类 CRL Changes）
    EntitySnapshot.cs          # 原始值快照 + Diff
    TrackingOptions.cs         # 排除列、比较器、大列策略
    EntityTracking.cs          # 静态门面：Begin / GetDiff / Attach
    EntityTrackingExtensions.cs # MarkDirty / Cumulate 扩展方法

挂钩（仅增强 Translator，**不修改** `SooRepository`）：
  EntityTranslator.prepareUpdateMembers / 主键不受 includeUpdate 过滤
  全部业务 API 落在 `SooRichRepo`（`new Update` / UpdateDirty / Track / …）
```

命名空间建议：`mooSQL.adoext.richRepo.tracking`。

### 3.3 核心类型设计

#### 3.3.1 `EntityChangeBag`（手动标记，对标 CRL `IModel.Changes`）

```csharp
namespace mooSQL.adoext.richRepo.tracking
{
    /// <summary>
    /// 实体脏字段袋。可不挂在实体上，由 Tracking 上下文持有。
    /// </summary>
    public sealed class EntityChangeBag
    {
        // propertyName → value；键以 '$' 前缀表示累加/表达式更新（对标 CRL Cumulation）
        readonly Dictionary<string, object> _changes = new(StringComparer.Ordinal);

        public void Set(string memberName, object value);
        public void SetCumulation(string memberName, object delta); // → "$Email"
        public bool IsModified { get; }
        public IReadOnlyDictionary<string, object> GetChanges();
        public void Clear();
    }
}
```

扩展方法（对标 `CRL.Data.ExtensionMethod.Change`）：

```csharp
// 读取当前属性值写入 bag（需外部 bag 或 ITrackedEntity）
entity.MarkDirty(x => x.Email);
entity.MarkDirty(x => x.Email, "n@x.com");   // 赋值 + 标记
entity.Cumulate(x => x.Score, 1);            // Score = Score + 1
```

**约束**：手动路径不要求继承；`EntityChangeBag` 可由：

- `ConditionalWeakTable<object, EntityChangeBag>` 附着，或  
- 可选 `ITrackedEntity.ChangeBag` 属性。

推荐 **WeakTable**，保持 POCO 干净。

#### 3.3.2 `EntitySnapshot`（主推，改造 CRL `ModelTracking`）

CRL 用 `GetHashCode` 比对，存在碰撞风险。mooSQL **存原始值**，用值相等比较。

```csharp
public sealed class EntitySnapshot
{
    readonly object _entity;
    readonly Type _entityType;
    readonly Dictionary<string, object> _origin; // PropertyName → boxed original
    readonly TrackingOptions _options;

    public EntitySnapshot(object entity, EntityInfo meta, TrackingOptions options = null);

    /// <summary>与当前实体属性逐字段比较，返回需更新的列字典（不含 PK）。</summary>
    public Dictionary<string, object> GetDiff();

    /// <summary>用当前值刷新快照（Update 成功后调用）。</summary>
    public void AcceptChanges();

    public bool HasChanges => GetDiff().Count > 0;
}
```

**比较规则**

| 类型 | 比较 |
|------|------|
| 值类型 / string | `Equals` / `string.Equals` |
| `byte[]` / 大 BLOB | 默认 **排除**（`TrackingOptions.ExcludeLargeTypes`）；或长度+可选深度比较 |
| 引用类型（导航） | 默认跳过（非列映射属性） |
| `null` | 与 origin null 相等则非脏 |

**构造时只快照已映射列**（`EntityInfo.Columns`），跳过 `Ignore` / 非持久化 / 导航属性。

#### 3.3.3 `TrackingOptions`

```csharp
public sealed class TrackingOptions
{
    /// <summary>永不参与脏检测的属性名（BLOB/JSON/审计列等）。</summary>
    public HashSet<string> ExcludeMembers { get; } = new(StringComparer.Ordinal);

    /// <summary>默认排除 byte[] / Stream 等大列。</summary>
    public bool ExcludeLargeTypes { get; set; } = true;

    /// <summary>无脏字段时：Throw | NoOp | FallBackAllColumns（默认 NoOp）。</summary>
    public DirtyEmptyBehavior EmptyBehavior { get; set; } = DirtyEmptyBehavior.NoOp;
}

public enum DirtyEmptyBehavior { NoOp, Throw, FallBackAllColumns }
```

**与 CRL 差异**：CRL 在无 Changes/Tracking 时静默全列更新；mooSQL **默认 NoOp**（返回 0 / false），全量必须显式 `UpdateAllColumns`，避免误伤。

#### 3.3.4 `EntityTracking` 门面

```csharp
public static class EntityTracking
{
    // 开始追踪（查询后或手动）
    public static EntitySnapshot Begin<T>(T entity, EntityInfo meta = null, TrackingOptions opt = null);

    public static void BeginRange<T>(IEnumerable<T> entities, ...);

    // 取 Diff：优先 Snapshot；其次 ChangeBag；皆无则按 EmptyBehavior
    public static IReadOnlyDictionary<string, object> GetDirtyMembers(object entity);

    public static bool IsTracked(object entity);
    public static void Detach(object entity);
    public static void AcceptChanges(object entity);
}
```

内部用 `ConditionalWeakTable<object, TrackingState>`：

```csharp
sealed class TrackingState
{
    public EntitySnapshot Snapshot;
    public EntityChangeBag Bag;
}
```

优先级：`Bag` 非空 → 用 Bag；否则 Snapshot Diff；否则 EmptyBehavior。

### 3.4 与 EntityTranslator 挂钩

在 `prepareUpdate` 增加「列白名单」入口（已有 `includeUpdateFields`，复用即可）：

```text
SooRepository.Update(entity)
  → dirty = EntityTracking.GetDirtyMembers(entity)
  → 若 dirty 为空 → EmptyBehavior
  → translator.includeUpdate(dirty.Keys).prepareUpdate(...)
  → 成功后 EntityTracking.AcceptChanges(entity)
  → 可选：RichRepo 写路径失效/补丁缓存
```

新增重载（或内部方法）：

```csharp
StatusResult prepareUpdate(
    SQLBuilder builder, object entity, Type entityType,
    IReadOnlyCollection<string> onlyMembers,  // null = 现有全列逻辑
    EntityInfo en = null, Func<string> loadName = null);
```

**Cumulation**：`$Member` → `builder.set(col, rawExpression)`，如 `Score = Score + @p`，方言由 Dialect 拼表达式（对标 CRL `GetFieldConcat`）。首期可仅支持数值 `+`；字符串 concat 按方言跟进。

### 3.5 SooRichRepo API（独立于 SooRepository）

`SooRepository` **保持不动**。以下 API 仅在 `SooRichRepo<T>` / `useRichRepo`：

```csharp
var repo = db.useRichRepo<User>().autoTrackOnQuery();

repo.Track(entity);
repo.Update(entity);           // 已追踪 → 脏更新；否则 base 全列
repo.UpdateDirty(entity);
repo.UpdateAllColumns(entity); // 显式全列 → base.Update
```

**兼容策略（重要）**

| 阶段 | `Update(entity)` 行为 |
|------|------------------------|
| 引入期（默认） | 已追踪 → 脏更新；未追踪 → **全列**（与现网兼容） |
| 文档推荐 | `autoTrackOnQuery(true)` + 业务统一 `Update` |
| 可选严格模式 | `TrackingMode.RequireTracked` → 未追踪抛异常 |

批量：`UpdateRange` 逐条走同一策略；大批量显式 `set` / `Update(columns, where)` 不走追踪。

### 3.6 查询自动追踪

在 `SooRepository.GetById` / `GetByIds` / `GetPageList` / 列表查询物化后：

```csharp
if (_autoTrack) EntityTracking.BeginRange(list, En, _trackingOptions);
```

Clip / Fast LINQ / Ext LINQ：**不默认**自动追踪（避免意外成本）；提供：

```csharp
.track()           // Clip 终止前标记：物化后 Begin
repo.Track(list)   // 显式
```

## 4. P0-2 富仓储 SooRichRepo — API 设计落实

### 4.1 定位（对标 CRL BaseProvider）

```text
SooRepository<T>              ← 薄 CRUD（保持默认）
    ↑
SooRichRepo<T>           ← 厚业务层（可选）：字典缓存、Schema、领域扩展点
```

- **不强制**业务继承 RichRepo；`useRepo` 仍是默认。  
- 代码落在 `pure/src/adoext/richRepo/`（命名空间 `mooSQL.adoext.richRepo`）；入口门面仍挂 `DBInstance.useRichRepo`。

### 4.2 类型与入口

```csharp
// pure/src/adoext/richRepo/SooRichRepo.cs
public class SooRichRepo<T> : SooRepository<T> where T : class, new()
{
    // —— 实体字典缓存（对标 BaseProvider）——
    public IEnumerable<T> AllCache { get; }
    public void ClearCache();
    protected virtual SQLBuilder CacheQuery();          // 或 SQLClip；定义预热范围，默认全表
    public List<T> QueryFromCache(Expression<Func<T, bool>> pred);
    public T QueryItemFromCache(object pk);
    public T QueryItemFromCache(Expression<Func<T, bool>> pred);

    // —— Schema UX（详见 §4.6）——
    public SchemaEnsureResult EnsureSchema(SyncMode mode = SyncMode.AddMissingColumns);
    public SchemaEnsureResult EnsureSchema(SchemaEnsureOptions options);
    public IReadOnlyList<string> PreviewSchema(SyncMode mode = SyncMode.AddMissingColumns);
    public void SyncFields(SyncMode mode = SyncMode.AddMissingColumns);
    public void SyncCaptions();

    // —— Upsert ——
    public int InsertOrUpdate(T entity, UpsertOptions options = null);
    public int InsertOrUpdate(IEnumerable<T> entities, UpsertOptions options = null);

    // —— 写路径钩子：失效字典缓存 ——
    protected virtual void OnAfterWrite(WriteKind kind, object entityOrKeys);
}

// Door
DBInstance.useRichRepo<T>()
MooClient / DBClientFactory 同步工厂方法
```

> `SyncMode` / `SchemaEnsureOptions` 定义见 **§4.6**，勿在业务代码直接传 `DMLOption.IsDropColumn`。

### 4.3 实体字典缓存（EntityCache）实现要点

与 **结果缓存（ResultCache）** 严格分离：

| | ResultCache | EntityCache（RichRepo） |
|--|-------------|------------------------|
| 键 | SQL + 参数 + DB 名（见 §5） | `Type.FullName + "|" + DatabaseName` |
| 值 | 查询结果集副本 | `Dictionary<string, T>`（PK → 实体） |
| 过滤 | SQL 侧 | **内存** `Compile().Invoke` / 简易表达式 |
| 失效 | TTL；写可选 Remove | 写后 Clear 或按 PK Patch |
| 分页 | **禁止缓存**（同 CRL） | 内存分页可选 |

```csharp
// 内部
sealed class EntityCacheStore
{
    // 复用 ISooCache 或独立 ConcurrentDictionary
    Dictionary<string, T> Warm(SooRichRepo<T> repo);
}

protected virtual SQLBuilder CacheQuery()
{
    // 默认：select * from T；子类可 where Status=1 缩小字典
    return DBLive.useSQL().select("*").from(En.DbTableName);
}
```

**TTL**：RichRepo 可配置 `EntityCacheSeconds`（默认 300，对标 CRL 5 分钟）；到期后下次访问重建。  
**写后策略（首期）**：`Insert/Update/Delete/InsertOrUpdate` → `ClearCache()`（简单正确）。  
**增强（二期）**：按 PK Patch（对标 CRL `UpdateCacheItem`）。

**主键等值短路**：`QueryFromCache(x => x.Id == id)` 走字典 TryGetValue（CRL 已有优化，应保留）。

### 4.4 富仓储完整 API 清单（落实）

继承 `SooRepository` 已有能力外，富仓储层保证暴露：

```text
# 缓存
AllCache / ClearCache / CacheQuery / QueryFromCache / QueryItemFromCache

# Schema
EnsureSchema / PreviewSchema / SyncFields / SyncCaptions → §4.6 SchemaEnsure

# Upsert
InsertOrUpdate(entity|list, UpsertOptions)

# 追踪（继承 Repo）
Update / UpdateDirty / UpdateAllColumns / Track / autoTrackOnQuery

# 可选领域扩展点
protected virtual void OnModelCreating(...)  // 预留，非必须首期

```

业务子类推荐写法：

```csharp
public class SysDictBiz : SooRichRepo<SysDict>
{
    protected override SQLBuilder CacheQuery()
        => base.CacheQuery().where("Enabled", 1);

    public string GetName(string code)
        => QueryItemFromCache(x => x.Code == code)?.Name;
}

// 使用
var dict = db.useRichRepo<SysDict>(); // 或 new SysDictBiz().Attach(db)
```

工厂：`useRichRepo<T>()` 返回 `SooRichRepo<T>`；若注册了自定义类型可通过 `IRichRepoFactory` 解析（二期）。

### 4.6 Schema 能力（EnsureSchema）— 详细实现

对标 CRL `CreateTable` / `SyncTableFields` / `UpdateTableFiledComments`，但 **默认绝不 DROP**（CRL `SyncTableFields` 会删多余列，不可照搬）。

#### 4.6.1 现状与缺口

| 能力 | 现状 | 说明 |
|------|------|------|
| `DDLBuilder.doInitTable` | ✅ | 无表则建；有表则 `doAlterTableLogic` |
| `DMLOption.IsDropColumn` | ✅ 默认 `false` | 仅显式 true 才删多余列 |
| 列类型修正 / PK / 注释 | ✅ 部分在 alter 路径 | 建表带 caption；alter 会补列注释 |
| `DBTableCreator` | 🟡 仅 create-if-missing | 有表即 return，补列逻辑死代码；**Ensure 勿依赖它** |
| `SyncMode` / `EnsureSchema` | ❌ | 缺产品化枚举与 RichRepo/DDL 门面 |
| 生产环境开关 | ❌ | 缺 `AllowSchemaSync` / 禁止 DROP 的全局闸 |

#### 4.6.3 `SyncMode` 与选项

```csharp
namespace mooSQL.adoext.richRepo.schema
{
    public enum SyncMode
    {
        /// <summary>仅当表不存在时 CREATE（含索引/注释）；已存在则跳过。</summary>
        CreateIfMissing = 0,

        /// <summary>推荐默认：无表则建；有表则只增加缺失列（及安全范围内的类型/PK/注释对齐）。不 DROP。</summary>
        AddMissingColumns = 1,

        /// <summary>在 AddMissingColumns 基础上刷新表/列注释。</summary>
        SyncCaptions = 2,

        /// <summary>危险：删除实体中不存在的 DB 列。须 Options.AllowDropColumn=true。</summary>
        AddAndDropExtraColumns = 9
    }

    public sealed class SchemaEnsureOptions
    {
        public SyncMode Mode { get; set; } = SyncMode.AddMissingColumns;

        /// <summary>生产可全局 false；为 false 时任何 Ensure 直接抛或 NoOp。</summary>
        public bool AllowSchemaSync { get; set; } = true;

        /// <summary>仅 Mode=AddAndDropExtraColumns 时生效；默认 false，双闸防误删。</summary>
        public bool AllowDropColumn { get; set; } = false;

        /// <summary>true → 调 toInitTableList，不执行。</summary>
        public bool PreviewOnly { get; set; } = false;

        /// <summary>分片物理表名；空则用实体默认表名。</summary>
        public string PhysicalTableName { get; set; }

        /// <summary>Preview 或执行后回填的 SQL 列表。</summary>
        public List<string> ScriptsOut { get; } = new();
    }
}
```

**双闸规则**：`AddAndDropExtraColumns` 且 `AllowDropColumn==true` 才映射 `DMLOption.IsDropColumn=true`；缺任一条件 → 按 `AddMissingColumns` 降级并打日志/警告。

#### 4.6.4 门面 API

```csharp
public static class SchemaEnsure
{
    public static SchemaEnsureResult Ensure<T>(DBInstance db, SchemaEnsureOptions opt = null);
    public static SchemaEnsureResult Ensure(DBInstance db, Type type, SchemaEnsureOptions opt = null);
    public static SchemaEnsureResult Ensure(DBInstance db, IEnumerable<Type> types, SchemaEnsureOptions opt = null);

    // Preview
    public static IReadOnlyList<string> Preview<T>(DBInstance db, SyncMode mode = SyncMode.AddMissingColumns);
}

public sealed class SchemaEnsureResult
{
    public bool Success { get; set; }
    public string Message { get; set; }
    public IReadOnlyList<string> Scripts { get; set; }
}
```

**RichRepo / DDL 入口**：

```csharp
// SooRichRepo<T>
public SchemaEnsureResult EnsureSchema(SyncMode mode = SyncMode.AddMissingColumns);
public SchemaEnsureResult EnsureSchema(SchemaEnsureOptions options);
public IReadOnlyList<string> PreviewSchema(SyncMode mode = SyncMode.AddMissingColumns);
public void SyncFields(SyncMode mode = SyncMode.AddMissingColumns); // → EnsureSchema 别名
public void SyncCaptions(); // → Mode=SyncCaptions

// Door（可选糖）
db.useDDL().ensure<T>(SyncMode.AddMissingColumns);
db.useDDL().ensure<T>(new SchemaEnsureOptions { PreviewOnly = true });
db.useRichRepo<User>().EnsureSchema();
```

对标 CRL Provider：

| CRL | mooSQL richRepo |
|-----|-----------------|
| `CreateTable()` | `EnsureSchema(CreateIfMissing)` |
| `SyncTableFields()` | `EnsureSchema(AddMissingColumns)`；DROP 须显式危险模式 |
| `UpdateTableFiledComments()` | `SyncCaptions()` / `SyncMode.SyncCaptions` |
| `CreateTableIndex()` | 含于 `doInitTable` 建表分支的 `doAddIndex`；缺索引补齐可作为二期 |

#### 4.6.5 执行映射

```text
EnsureSchema(opt)
  → if !AllowSchemaSync → fail / no-op（可配置）
  → map SyncMode → DMLOption:
       CreateIfMissing      → 仅 hasTable? skip : doInitTable(无 alter)
       AddMissingColumns    → doInitTable(IsDropColumn=false)
       SyncCaptions         → doInitTable(false) + 注释刷新路径
       AddAndDropExtra…     → 双闸通过则 IsDropColumn=true
  → PreviewOnly ? toInitTableList : doInitTable
  → ScriptsOut 回填
```

`CreateIfMissing` 实现注意：若表已存在应 **跳过 alter**（与 `AddMissingColumns` 区分）；可先 `hasTable` 再分支。

分片表：`PhysicalTableName` 非空时，走带物理表名的 init/create 路径（对接现有分片 DDL / `ShardDdlHelper`；若仅 create-only，文档标明首期限制）。

#### 4.6.6 安全与环境

| 场景 | 策略 |
|------|------|
| 开发 / 测试 | 默认 `AddMissingColumns` |
| 生产 | `AllowSchemaSync=false` 或仅 Preview；禁止 Drop |
| CI | `PreviewOnly` 断言无意外 DROP 脚本 |
| 多库 | 尊重 `entity.DBPosition`（`doInitTable` 已有跳过逻辑） |

客户端级开关建议：

```csharp
client.configureSchema(c => {
    c.AllowSchemaSync = env.IsDevelopment();
    c.AllowDropColumn = false;
});
```

（配置挂 `MooClient` / `BaseClientBuilder`，`SchemaEnsure` 读取。）

## 5. P0-3 查询链统一缓存语义

### 5.1 目标

Clip / Fast LINQ / Ext LINQ / SQLBuilder **同一套**：

- `.expire(TimeSpan ttl)` 或 `.useCache(key, ttl)`  
- 底层均走 `ISooCache`（`Client.Cache` / `setCacheHolder`）  
- 文档区分 **结果缓存** vs **实体字典缓存**

### 5.2 Key 规则

```text
ResultCacheKey = "RC:" + Hash(
    databaseName + "\n" +
    sqlText + "\n" +
    normalizedParams
)
```

- 显式 `useCache("myKey", ttl)` 时：`RC:USER:myKey`（仍建议附带 DB 名防串库）。  
- 分页查询（`setPage` / `skipTake` 且 pageIndex>0 或 skip>0）：**默认不缓存**（与 CRL 一致）；若强制缓存须显式 key + 文档警告。  
- 事务开启中：默认跳过读缓存与写缓存（避免脏读进缓存）。

### 5.3 API

```csharp
// SQLBuilder（已有 → 增加 TimeSpan 重载）
kit.setCache(key, timeoutSeconds);
kit.expire(TimeSpan.FromMinutes(5));          // 自动 key

// SQLClip
clip.from<User>().where(...).expire(ttl).queryList();
clip.useCache("users:active", ttl).queryList();

// Fast / Ext LINQ
q.Where(...).Expire(ttl).ToList();            // 命名可与现有风格对齐为 expire
```

### 5.4 与 SooRichRepo 的关系

- `.expire` = ResultCache，缓存 **本次 SQL 结果**。  
- `QueryFromCache` = EntityCache，缓存 **整表/子集字典**。  
- 二者不要混用同一文档示例而不加说明。

## 6. P0-4 UpsertOptions + Repo InsertOrUpdate

文件：`pure/src/adoext/richRepo/UpsertOptions.cs`（Repo / RichRepo 共用）。

### 6.1 选项对象（对标 CRL `InsertOrUpdateOption`，跨方言）

```csharp
public sealed class UpsertOptions
{
    /// <summary>唯一判定列；空则用 PK。</summary>
    public List<string> ConstraintMembers { get; } = new();

    /// <summary>匹配后要更新的列；空则更新除约束列外全部可更新列。</summary>
    public List<string> UpdateMembers { get; } = new();

    /// <summary>存在则跳过更新（仅插入）。</summary>
    public bool IfExistsSkipUpdate { get; set; }

    /// <summary>批量切片大小；0 = 方言默认。</summary>
    public int BatchSize { get; set; } = 500;

    /// <summary>调试：最后生成的 SQL（可选 out）。</summary>
    public string SqlOut { get; set; }
}
```

### 6.2 方言策略

| 方言 | 实现 |
|------|------|
| SQL Server / Oracle | 现有 MERGE 管线 |
| MySQL | ON DUPLICATE KEY UPDATE |
| PostgreSQL | ON CONFLICT (... ) DO UPDATE/NOTHING |
| 其它 | 能则方言后缀；否则抛「不支持」或降级「先查后写」（需文档标注） |

入口：

```csharp
repo.InsertOrUpdate(entity, options);
richRepo.InsertOrUpdate(list, options);  // 按 BatchSize 切片
```

内部复用 `MergeIntoBuilder` / `InsertOrUpdateSentence`，由 `EntityTranslator` 填列。

## 7. P1 CASE / Window 一等 API（Clip）

### 7.1 设计（对标 CRL CaseExpression / WindowFuncExpression）

CRL 模式：链式拼 SQL 片段，实现 `IQuery.GetQuery()`，嵌入 Select。  
mooSQL：在 Clip 暴露，**落到已有** `CaseWord` / `WindowOverClause` / `SQLExpression`，避免纯字符串方言漏洞；When 字面量 **参数化**。

```csharp
// Clip 工厂
var caseExpr = clip.caseWhen<Order>()
    .when(x => x.Status == 1).then("待付")
    .when(x => x.Status == 2).then("已付")
    .else_("关闭")
    .end();

var rn = clip.window<Order>()
    .rowNumber()
    .over()
        .partitionBy(x => x.UserId)
        .orderBy(x => x.Id, desc: true)
    .end();

// 用于 select 投影
clip.from<Order>()
    .select(o => new { o.Id, Flag = caseExpr, Rn = rn });
```

Fast LINQ：可薄封装调用同一 Builder；Ext LINQ 已有 Analytic，保持并行不替代。

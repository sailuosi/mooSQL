# mooSQL 命名空间规范

> **状态**：规范草案（先定规范，再实施迁移）  
> **适用范围**：全库；**近期实施范围**仅 `ext/src/linq`  
> **关联**：`pure` 现状为事实基线；Ext LINQ 对齐本规范后再改代码  

---

## 1. 目标

1. 业务侧日常 `using` 尽量少、稳定：绝大多数入口与常用 API 落在 **`mooSQL.data`**。
2. Queryable / LINQ 查询面统一落在 **`mooSQL.linq`**（Fast LINQ 与 Ext LINQ 共用此根）。
3. 内部实现命名空间**最多再加一层**（相对 `mooSQL.data` 或 `mooSQL.linq`），禁止再嵌套。
4. 目录结构可逐步整理；**以命名空间为准**，目录不必与命名空间一一镜像。

---

## 2. 根命名空间一览

| 根命名空间 | 用途 | 业务侧是否常用 |
|------------|------|----------------|
| `mooSQL.data` | 数据库访问主面：连接/方言/SQLBuilder/仓储/门面扩展（`useXxx`） | **是** |
| `mooSQL.linq` | 全部 Queryable 相关：`IDbBus` / `IDbQuery`、LINQ 扩展、DbFunc、表达式查询契约 | **是（写 LINQ 时）** |
| `mooSQL.utils` | 与数据库无关的通用扩展与工具 | 按需 |
| `mooSQL.config` | 配置注册 | 按需 |
| `mooSQL.auth` / `mooSQL.excel` / `mooSQL.ftp` / `mooSQL.meta` | 独立子系统 | 按需 |

新增能力时：**优先挂到已有根下的一层子空间**；不要新增第四个「业务常用根」。

---

## 3. 分层与深度规则

### 3.1 深度上限

合法形态：

```
mooSQL.{root}                 // 第 2 层：公开主面
mooSQL.{root}.{layer}         // 第 3 层：子系统 / 内部实现
```

**禁止**（实施后不得新增；存量待收敛）：

```
mooSQL.{root}.{layer}.{sub}           // 第 4 层
mooSQL.{root}.{layer}.{sub}.{more}    // 第 5 层及更深
```

例外（历史遗留，仅文档登记，新代码不得效仿）：

| 现状 | 说明 |
|------|------|
| `mooSQL.data.clip.project` | clip 子能力，后续可评估并入 `clip` |
| `mooSQL.data.model.affirms` | model 子能力，后续可评估并入 `model` |
| Ext LINQ 深层树 | 见 §6，列为迁移目标 |

### 3.2 业务面 vs 内部面

| 类别 | 命名空间 | 可见性建议 | 示例 |
|------|----------|------------|------|
| 业务入口 | `mooSQL.data` | `public` | `useSQL`、`useQueryable`、`useBus`、`useRichRepo` |
| 业务查询契约 | `mooSQL.linq` | `public` | `IDbQuery<T>`、`IDbBus<T>`、`DbFunc`、`LinqExtensions` |
| 子系统 API | `mooSQL.data.{layer}` | 多数 `public`，但业务日常可不 using | `data.call`、`data.model`、`data.mapping`、`data.clip` |
| 内部实现 | `mooSQL.linq.{layer}` 等 | 优先 `internal` | `linq.builder`、`linq.translator`、`linq.utils` |

**原则**：业务代码理想引用为：

```csharp
using mooSQL.data;   // 入口
using mooSQL.linq;   // 写 Queryable / DbFunc / LINQ 扩展时
```

## 4. 命名约定

### 4.1 大小写

- **根名**保持现有形态：`mooSQL.data`、`mooSQL.linq`（均为小写段）。
- **`mooSQL.data` / `mooSQL.linq` 的下级子层：一律小写开头**（与 `data.call`、`data.model`、`linq.translator` 一致）。
  - 单词语：全小写，如 `builder`、`translator`、`mapping`、`clause`、`provider`、`utils`。
  - 多词语：camelCase 且首字母小写（尽量少用；优先单词语）。
- **禁止**在 `mooSQL.linq` 下再新增 PascalCase 子层（如存量 `Linq`、`Expressions`、`Mapping`、`SqlQuery`、`Common`、`Async`）——迁移时改为小写开头对应名（语句 IR → `clause`，见 §6.3）。
- 单词完整可读；禁止无语义缩写造词作为长期子层名（如业务扩展误放的 `ext` → 合并进主面）。

### 4.2 禁止冗余嵌套

- 禁止 `mooSQL.linq.Linq.*`（根已含 linq，子层不得再叫 `Linq` / `linq`）。
- 禁止 `mooSQL.data.Data.*` 同类冗余嵌套。
- **禁止**使用 `mooSQL.linq.data`（易与 `mooSQL.data` 混淆）→ 相关类型并入 **`mooSQL.linq.utils`**。

### 4.3 与目录的关系

- 物理目录可按模块拆分（`door/`、`translator/`、`src/api/`），**不强制**目录名等于命名空间最后一段。
- 同一命名空间可跨多个目录；同一目录内**不宜**混用多个对外根（`data` 与 `linq` 可并存于入口文件，但应集中在 `door/` 一类目录）。

### 4.4 兼容 / 第三方命名空间

- 仅用于 BCL / 第三方兼容的类型可保留原命名空间（如 `System.Data.Linq`），不纳入 mooSQL 树。
- 不得把第三方命名空间当作 mooSQL 内部组织手段。

## 5. `mooSQL.data` 细则

### 5.1 主面（无子层）

放入 `mooSQL.data` 的类型：

- `DBInstance` 上的 **`useXxx` / `AsXxx` 门面扩展**
- 业务高频类型：`SQLBuilder`、仓储基类、UnitOfWork 等（与现 pure 一致）
- 与「如何拿到能力」直接相关的薄封装

### 5.2 允许的一层子空间（pure 基线）

| 子空间 | 职责 |
|--------|------|
| `mooSQL.data.call` | MethodCall / Visitor 调用链 |
| `mooSQL.data.model` | 实体模型、表列元数据 |
| `mooSQL.data.mapping` | 类型映射面板 |
| `mooSQL.data.clip` | SQLClip |
| `mooSQL.data.context` | 执行上下文 |
| `mooSQL.data.cluster` / `slave` / `health` / `builder` / `reader` / `translation` / `utils` | 各专项子系统 |
| `mooSQL.data.linq` | 与 LINQ 交叉、但属于 data 模型侧的少量类型（保持极少） |
| `mooSQL.data.Extensions` | 高级反射等扩展（业务低频） |

新增子空间须满足：职责独立、文件量可观、且不能用现有子空间表达。

### 5.3 门面扩展强制规则

凡扩展方法签名为 `this DBInstance`（或等价数据库入口）且命名为 `use*` / `As*`：

- 命名空间必须为 **`mooSQL.data`**
- 即使实现文件位于 `ext/src/linq/door/` 或 `pure/src/linq/`

## 6. `mooSQL.linq` 细则

### 6.1 定位

`mooSQL.linq` 表示 **所有 Queryable 相关能力**（Fast + Ext），不是「仅 Ext」或「仅内部」。

| 能力线 | 入口（`mooSQL.data`） | 查询类型（`mooSQL.linq`） |
|--------|----------------------|---------------------------|
| Fast LINQ | `useBus` / `useDbBus` | `IDbBus<T>`、`BusQueryable` 等 |
| Ext LINQ | `useQueryable` / `AsQueryable` | `IDbQuery<T>`、`LinqExtensions` 等 |

### 6.2 主面（无子层）——业务/查询应感知的类型

应落在 **`mooSQL.linq`**（禁止再挂到 `.ext` / `.Linq` / `.utils` 等内部子层）：

| 类别 | 示例 |
|------|------|
| 查询根接口 | `IDbQuery`、`IDbQuery<T>`、`IDbQueryMutable`、`IDbBus` 等 |
| Queryable 扩展 | `LinqExtensions`（含 Insert/Update/Delete/Merge/Includes 等 partial） |
| 异步扩展 | `AsyncExtensions` 及面向用户的 async 扩展 |
| 方言函数 | `DbFunc`、`SooFunc`、`SooFunctionExtension` |
| 翻译/扩展特性 | `ExpressionAttribute`、`QueryExtensionAttribute`、`TableFunctionAttribute` 等 |
| DML/链式契约 | `IUpdatable`、`IMergeable*`、`ISelectInsertable`、`IValueInsertable`、`IMultiInsert*` 等 |
| 实体侧标注 | `AssociationAttribute` 等业务会写在实体上的特性 |
| 查询侧配置 | `ExtLinqOptions`（或同类 Options） |
| 用户可见异常 | `LinqException`、`SooQueryException` |

### 6.3 允许的一层子空间（内部实现）

实施 Ext LINQ 收敛时，目标子空间如下（**全部为第 3 层、小写开头，不再加深**）：

| 目标命名空间 | 职责 | 主要迁入自（现状） |
|--------------|------|-------------------|
| `mooSQL.linq.builder` | 编译上下文、ClauseSqlTranslator、clauseContext | `mooSQL.linq.Linq.Builder`、部分 `Linq` |
| `mooSQL.linq.translator` | Expression → SentenceBag → 执行 | `mooSQL.linq.translator`（保持）、`core` |
| `mooSQL.linq.expressions` | 表达式辅助、特殊 Expression 节点 | `mooSQL.linq.Expressions` |
| `mooSQL.linq.clause` | 语句树 / Clause IR（SelectQueryClause、Sentence*、语句级 Visitor 等） | `SqlQuery`、`SqlQuery.Visitors`、`src/clause/`（Visitors **并入**本层，不再单独子空间） |
| `mooSQL.linq.mapping` | 仅内部映射描述符（非实体标注） | 描述符类；特性见 §6.2 |
| `mooSQL.linq.provider` | SQL 优化与提供器辅助 | `SqlProvider`、`DataProvider` |
| `mooSQL.linq.utils` | 反射、通用转换、文本、缓存、Activity、参数/构造等横切与内部辅助 | `Reflection`、`Common`（含 Internal/Cache）、`Tools`、`Infrastructure`、`Data` |

**Translation** 成员翻译器：优先并入 `translator` 或 `builder` 之一，**不单独**保留 `Linq.Translation` 第四层。

> **语句 IR 命名**：凡与「语句 / Clause」相关的类型，统一落在 **`mooSQL.linq.clause`**。  
> **`mooSQL.linq.sqlQuery` / `mooSQL.linq.SqlQuery` 一律废除**（含 `.Visitors`），不得作为目标或新增；pure 存量 `SqlQuery` 后续迁入 `clause`。  
> **横切与提供器**：`sqlProvider` → **`provider`**；`reflection` / `common` / `tools` / **`data`** → 一律并入 **`utils`**（不得再作为目标子空间；尤其禁止 `linq.data`，以免与 `mooSQL.data` 混淆）。

### 6.4 明确废止的命名空间（存量，迁移后删除）

| 废止 | 原因 | 去向 |
|------|------|------|
| `mooSQL.linq.ext` | 业务扩展误放子层 | → `mooSQL.linq` |
| `mooSQL.linq.Extensions` | 与 `ext` 分裂、PascalCase | 公开 → `mooSQL.linq`；内部 → `utils` |
| `mooSQL.linq.Linq` | 冗余嵌套、PascalCase | 契约 → `mooSQL.linq`；实现 → `builder` / `translator` |
| `mooSQL.linq.Linq.Builder` | 超深 | → `mooSQL.linq.builder` |
| `mooSQL.linq.Linq.Builder.Visitors` | 超深 | → `mooSQL.linq.builder` |
| `mooSQL.linq.Linq.Translation` | 超深 | → `translator` 或 `builder` |
| `mooSQL.linq.Common` / `.Internal` / `.Internal.Cache` | 并入 utils、且超深 | → **`mooSQL.linq.utils`** |
| `mooSQL.linq.common` / `mooSQL.linq.tools` | 曾拟目标名，现废除 | → **`mooSQL.linq.utils`** |
| `mooSQL.linq.Reflection` / `mooSQL.linq.reflection` | 并入 utils | → **`mooSQL.linq.utils`** |
| `mooSQL.linq.Tools` | 并入 utils | → **`mooSQL.linq.utils`** |
| `mooSQL.linq.Infrastructure` | 语义空泛 | → **`mooSQL.linq.utils`** |
| `mooSQL.linq.Expressions` | PascalCase | → `mooSQL.linq.expressions` |
| `mooSQL.linq.SqlQuery` / `.Visitors` | 命名废除 + 超深 | → **`mooSQL.linq.clause`** |
| `mooSQL.linq.sqlQuery` | 曾拟替代名，现废除 | → **`mooSQL.linq.clause`** |
| `mooSQL.linq.SqlProvider` / `mooSQL.linq.sqlProvider` | 改名为 provider | → **`mooSQL.linq.provider`** |
| `mooSQL.linq.Data` / `mooSQL.linq.data` | 易与 `mooSQL.data` 混淆 | → **`mooSQL.linq.utils`** |
| `mooSQL.linq.Mapping` / `Async` | PascalCase 或过碎 | → `mapping`，或并入主面 / `utils` |
| `mooSQL.linq.core` | 职责模糊 | → `translator` |
| `mooSQL.linq.DataProvider` | 过碎 | → `provider` |

## 7. Ext LINQ 与 `mooSQL.data` 的边界

保留在 **`mooSQL.data`**（已符合规范，迁移时勿改走）：

| 类型 / 文件区 | 说明 |
|---------------|------|
| `DBExtLinqExtension` | `useQueryable` / `AsQueryable` |
| `ExtCompiledQueryExtensions` | 编译查询入口扩展 |
| `SQLClipLinqExtensions` | SQLClip ↔ LINQ 桥 |
| `ExtLinqEntry`（可为 `internal`） | 创建 `IDbQuery` 的工厂 |

业务侧典型引用：

```csharp
using mooSQL.data;
using mooSQL.linq;

var q = db.useQueryable<User>()
    .Where(u => DbFunc.Like(u.Name, "%a%"));
```

## 8. 可见性与 InternalsVisibleTo

1. 仅编译器/执行器使用的类型：优先 **`internal`**，命名空间仍用 §6.3 一层子空间。
2. 不要用「很深的命名空间」代替 `internal` 来隐藏 API。
3. 测试 / 方言程序集若需访问 internal，使用 `InternalsVisibleTo`，而不是把类型改成 `public` 并挂到深层命名空间。

## 9. 新增代码检查清单

提交涉及命名空间的改动前自检：

- [ ] 业务入口是否在 `mooSQL.data`？
- [ ] Queryable / DbFunc / LINQ 扩展是否在 `mooSQL.linq`？
- [ ] 是否出现第 4 层及以上命名空间？
- [ ] 是否出现 `linq.Linq`、`linq.ext`、或 `linq` 下 PascalCase 子层等废止形态？
- [ ] `mooSQL.linq.*` 子层是否均为小写开头？
- [ ] 公开 API 是否可以用「最多两个 using」（`data` + `linq`）完成主路径？
- [ ] 内部类型是否优先 `internal`？

## 10. 实施范围与顺序（规范落地，非本文件执行）

| 阶段 | 范围 | 说明 |
|------|------|------|
| **P0** | 仅文档（本规范） | 评审确认 |
| **P1** | `ext/src/linq` 内部深层 ns 压扁 | 先 `builder` / `utils` / `clause`（原 SqlQuery + Visitors），降低破坏面 |
| **P2** | 公开面合并 | `.ext` → `mooSQL.linq`；特性与 Options 归位 |
| **P3** | 同步引用方 | `ext/src/provides`、Tests、文档中的 `using` |
| **P4** | （可选）目录整理 | 如 `api/` 重命名；与 ns 解耦，可后置 |

**明确非本轮范围**：`pure` 命名空间大迁移；`data.clip.project` 等历史例外。

## 11. 已定决策摘要

| # | 决策 |
|---|------|
| 1 | 业务绝大多数 API → `mooSQL.data` |
| 2 | 全部 Queryable 相关 → `mooSQL.linq`（Fast 与 Ext 共用） |
| 3 | 内部最多再一层；禁止第 4 层+ |
| 4 | `mooSQL.linq`（及 `data`）下级子层一律**小写开头**；废止 PascalCase 子层（`Linq` / `Expressions` / `SqlQuery` 等） |
| 5 | 入口 `use*` 固定 `mooSQL.data`；查询类型与 LINQ 扩展固定 `mooSQL.linq`（不把 `IDbQuery` 迁入 `data`） |
| 6 | 语句 / Clause IR 统一为 **`mooSQL.linq.clause`**；**废除** `sqlQuery` / `SqlQuery`（含 Visitors） |
| 7 | `sqlProvider` → **`provider`**；`reflection` / `common` / `tools` / **`data`** → 一律并入 **`utils`**（禁止 `linq.data`） |
| 8 | 近期实施范围仅 `ext/src/linq`（引用方随 P3 同步） |

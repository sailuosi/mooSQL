# mooSQL 命名空间规范

> **状态**：现行规范（Ext LINQ 已按本规范落地）  
> **适用范围**：全库新代码与重构；以本文件为准  

---

## 1. 目标

1. 业务侧日常 `using` 尽量少、稳定：绝大多数入口与常用 API 落在 **`mooSQL.data`**。
2. Queryable / LINQ 查询面统一落在 **`mooSQL.linq`**（Fast LINQ 与 Ext LINQ 共用此根）。
3. 内部实现命名空间**最多再加一层**（相对 `mooSQL.data` 或 `mooSQL.linq`），禁止再嵌套。
4. **以命名空间为准**，物理目录不必与命名空间一一镜像。

业务代码理想引用：

```csharp
using mooSQL.data;   // 入口
using mooSQL.linq;   // 写 Queryable / DbFunc / LINQ 扩展时
```

---

## 2. 根命名空间

| 根命名空间 | 用途 | 业务侧是否常用 |
|------------|------|----------------|
| `mooSQL.data` | 数据库访问主面：连接/方言/SQLBuilder/仓储/门面扩展（`useXxx`） | **是** |
| `mooSQL.linq` | 全部 Queryable 相关：`IDbBus` / `IDbQuery`、LINQ 扩展、DbFunc、查询契约 | **是（写 LINQ 时）** |
| `mooSQL.utils` | 与数据库无关的通用扩展与工具 | 按需 |
| `mooSQL.config` | 配置注册 | 按需 |
| `mooSQL.auth` / `mooSQL.excel` / `mooSQL.ftp` / `mooSQL.meta` | 独立子系统 | 按需 |

新增能力时：**优先挂到已有根下的一层子空间**；不要新增第四个业务常用根。

---

## 3. 深度与分层

### 3.1 深度上限

```
mooSQL.{root}                 // 公开主面
mooSQL.{root}.{layer}         // 子系统 / 内部实现（最多一层）
```

禁止第 4 层及以上（`mooSQL.{root}.{layer}.{sub}`）。

存量例外（新代码不得效仿）：

| 命名空间 | 说明 |
|----------|------|
| `mooSQL.data.clip.project` | clip 子能力 |
| `mooSQL.data.model.affirms` | model 子能力 |
| `mooSQL.linq.SqlQuery`（pure） | 语句 IR；新 Ext 代码用 `mooSQL.linq.clause`，pure 后续对齐 |

### 3.2 业务面 vs 内部面

| 类别 | 命名空间 | 可见性 | 示例 |
|------|----------|--------|------|
| 业务入口 | `mooSQL.data` | `public` | `useSQL`、`useQueryable`、`useBus` |
| 业务查询契约 | `mooSQL.linq` | `public` | `IDbQuery<T>`、`DbFunc`、`LinqExtensions` |
| 子系统 API | `mooSQL.data.{layer}` | 多为 `public` | `call`、`model`、`mapping`、`clip` |
| 内部实现 | `mooSQL.linq.{layer}` | 优先 `internal` | `builder`、`translator`、`utils` |

---

## 4. 命名约定

### 4.1 大小写

- 根名：`mooSQL.data`、`mooSQL.linq`（小写段）。
- **下级子层一律小写开头**：单词语全小写（`builder`、`clause`、`utils`）；多词语用 camelCase 且少用。
- 禁止在 `mooSQL.linq` 下新增 PascalCase 子层。
- 单词完整可读；禁止无语义缩写作为长期子层名。

### 4.2 禁止

- `mooSQL.linq.Linq.*`、`mooSQL.data.Data.*` 等冗余嵌套。
- `mooSQL.linq.data`（易与 `mooSQL.data` 混淆）→ 横切辅助用 **`mooSQL.linq.utils`**。

### 4.3 目录

- 目录可按模块拆分（如 `door/`、`translator/`）；不强制等于命名空间最后一段。
- 同一目录内不宜混用多个对外根；`data` 入口扩展宜集中在 `door/` 一类目录。

### 4.4 第三方

- BCL / 第三方兼容类型可保留原命名空间（如 `System.Data.Linq`）。
- 不得把第三方命名空间当作 mooSQL 内部组织手段。

---

## 5. `mooSQL.data`

### 5.1 主面

- `DBInstance` 上的 **`useXxx` / `AsXxx` 门面扩展**
- 业务高频类型：`SQLBuilder`、仓储、UnitOfWork 等
- 与「如何拿到能力」直接相关的薄封装

### 5.2 一层子空间

| 子空间 | 职责 |
|--------|------|
| `mooSQL.data.call` | MethodCall / Visitor 调用链 |
| `mooSQL.data.model` | 实体模型、表列元数据 |
| `mooSQL.data.mapping` | 类型映射面板 |
| `mooSQL.data.clip` | SQLClip |
| `mooSQL.data.context` | 执行上下文 |
| `mooSQL.data.cluster` / `slave` / `health` / `builder` / `reader` / `translation` / `utils` | 各专项子系统 |
| `mooSQL.data.linq` | data 侧与 LINQ 交叉的少量类型（保持极少） |
| `mooSQL.data.Extensions` | 高级反射等（业务低频） |

新增子空间须职责独立、体量可观，且不能用现有子空间表达。

### 5.3 门面强制规则

扩展方法签名为 `this DBInstance`（或等价入口）且命名为 `use*` / `As*` 时，命名空间必须为 **`mooSQL.data`**（无论文件在 pure 还是 `ext/src/linq/door/`）。

---

## 6. `mooSQL.linq`

### 6.1 定位

表示 **所有 Queryable 相关能力**（Fast + Ext）。

| 能力线 | 入口（`mooSQL.data`） | 查询类型（`mooSQL.linq`） |
|--------|----------------------|---------------------------|
| Fast LINQ | `useBus` / `useDbBus` | `IDbBus<T>` 等 |
| Ext LINQ | `useQueryable` / `AsQueryable` | `IDbQuery<T>`、`LinqExtensions` 等 |

### 6.2 主面（业务应感知）

落在 **`mooSQL.linq`**，不要挂到内部子层：

| 类别 | 示例 |
|------|------|
| 查询根接口 | `IDbQuery`、`IDbQuery<T>`、`IDbBus` 等 |
| Queryable 扩展 | `LinqExtensions`（含 DML / Includes 等 partial） |
| 异步扩展 | `AsyncExtensions` 等面向用户的 async 扩展 |
| 方言函数 | `DbFunc`、`SooFunc`、`SooFunctionExtension` |
| 翻译/扩展特性 | `ExpressionAttribute`、`QueryExtensionAttribute` 等 |
| DML/链式契约 | `IUpdatable`、`IMergeable*`、`IMultiInsert*` 等 |
| 实体标注 | `AssociationAttribute` 等 |
| 查询配置 | `ExtLinqOptions` |
| 用户可见异常 | `LinqException`、`SooQueryException` |

### 6.3 一层子空间（内部）

| 命名空间 | 职责 |
|----------|------|
| `mooSQL.linq.builder` | 编译上下文、ClauseSqlTranslator、clauseContext |
| `mooSQL.linq.translator` | Expression → SentenceBag → 执行；成员翻译器 |
| `mooSQL.linq.expressions` | 表达式辅助、特殊 Expression 节点 |
| `mooSQL.linq.clause` | 语句树 / Clause IR（含语句级 Visitor） |
| `mooSQL.linq.mapping` | 内部映射描述符（非实体标注） |
| `mooSQL.linq.provider` | SQL 优化与提供器辅助 |
| `mooSQL.linq.utils` | 反射、转换、文本、缓存、Activity 等横切辅助 |

### 6.4 Ext 入口归属 `mooSQL.data`

| 类型 | 说明 |
|------|------|
| `DBExtLinqExtension` | `useQueryable` / `AsQueryable` |
| `ExtCompiledQueryExtensions` | 编译查询入口 |
| `SQLClipLinqExtensions` | SQLClip ↔ LINQ 桥 |
| `ExtLinqEntry` | 可为 `internal` 的工厂 |

---

## 7. 可见性

1. 仅编译器/执行器使用的类型：优先 **`internal`**，命名空间仍用一层子空间。
2. 不要用深层命名空间代替 `internal`。
3. 测试 / 方言需访问 internal 时用 `InternalsVisibleTo`。

---

## 8. 新增代码检查清单

- [ ] 业务入口是否在 `mooSQL.data`？
- [ ] Queryable / DbFunc / LINQ 扩展是否在 `mooSQL.linq`？
- [ ] 是否出现第 4 层及以上命名空间？
- [ ] `mooSQL.linq.*` 子层是否均为小写开头？
- [ ] 是否避免了 `linq.data`、冗余 `Linq` 嵌套、PascalCase 子层？
- [ ] 主路径是否可用 `using mooSQL.data` + `using mooSQL.linq` 完成？
- [ ] 内部类型是否优先 `internal`？

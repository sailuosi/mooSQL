# 业务仓储与缓存指南

> 对应实施文档：`doc/design/plan/业务层与查询体验-实施文档.md`  
> 修订：2026-08-11

## 1. 选用哪条门面

| 需求 | 入口 |
|------|------|
| 薄 CRUD、与现网一致 | `db.useRepo<T>()` |
| 脏更新 / 字典缓存 / Schema / Upsert | `db.useRichRepo<T>()` |
| 拼 SQL / CASE·Window / SELECT 结果缓存 | `db.useSQL()`（`setCache`） |
| 强类型片段 | `db.useClip()` |
| 同库多 API 事务 | `db.useTrans(work => …)` |
| 延迟批量提交 | `db.useWork()`（语义不同于 useTrans） |

**原则**：业务厚 API **只**进富仓储；SQL 特性挂 Builder/Clip，不绑死 RichRepo。

## 2. 脏字段追踪

```csharp
var repo = db.useRichRepo<User>().autoTrackOnQuery();
var user = repo.GetById(1);   // 自动 Begin 快照
user.Email = "n@x.com";
repo.Update(user);            // 仅 SET Email
repo.UpdateAllColumns(user);  // 逃生：全列
```

`autoTrackOnQuery` 覆盖：`GetById` / `GetByIds` / `GetList` 各重载 / `GetPageList` 各重载。  
未追踪时 `Update` 默认全列（`TrackingOptions.UntrackedUpdateAllColumns = true`）。

手动标记：

```csharp
entity.MarkDirty(x => x.Email);
entity.Cumulate(x => x.Score, 1); // Score = Score + @p
repo.UpdateDirty(entity);
```

薄仓 `useRepo` **无** Track / UpdateDirty，行为与改造前一致。

## 3. 两种缓存（勿混用）

| | ResultCache | EntityCache |
|--|-------------|-------------|
| 入口 | `kit.setCache(key,ttl)` 或 `setCache(ttl)` | `useRichRepo`：`AllCache` / `QueryFromCache` |
| 键 | 业务 key 或 SQLCmd 指纹 | 实体类型 + 库 |
| 值 | 单次 SELECT 结果 | PK→实体字典 |
| 失效 | TTL；事务中跳过 | 写后 `ClearCache` |

**不提供** Clip / LINQ `.expire`。结果缓存细节见 `SQLBuilder-Select结果缓存-实施计划.md`。

主从延迟：字典缓存与结果缓存均可能读到从库滞后数据；写后失效只保证本进程字典；跨进程需自管 TTL 或禁缓存。

## 4. SchemaEnsure

```csharp
db.useRichRepo<User>().EnsureSchema(SyncMode.AddMissingColumns);
db.useRichRepo<User>().PreviewSchema(); // 只看 SQL
db.useDDL().ensure<User>();

client.configureSchema(c => {
    c.AllowSchemaSync = env.IsDevelopment();
});
```

默认 **不 DROP**。`AddAndDropExtraColumns` 须 `AllowDropColumn=true` 双闸。生产建议 `AllowSchemaSync=false` 或仅 Preview。

## 5. Upsert

```csharp
db.useRichRepo<User>().InsertOrUpdate(user, new UpsertOptions {
    ConstraintMembers = { nameof(User.UserName) },
    UpdateMembers = { nameof(User.Email) },
    IfExistsSkipUpdate = false,
    BatchSize = 500
});
```

策略：MySQL（`IsInsertOrUpdateSupported`）→ `ON DUPLICATE KEY UPDATE`；MSSQL/Oracle/PG/Oscar/DM → `MERGE`；否则 **先查后写**（`SqlOut` 带 `select-write:` 前缀）。薄仓不提供此 API。

## 6. useTrans

```csharp
db.useTrans(work =>
{
    work.useRichRepo<User>().Update(user);
    work.useRepo<Order>().Insert(order);
    work.useSQL().setTable("…").doUpdate();
    return true; // false → 回滚
});
```

同库、共享一个 `DBExecutor`。跨库不伪装分布式事务。与 `useWork`（延迟 BatchSQL）不同。

## 7. Include

```csharp
var list = db.useRepo<User>().GetList(x => x.Id == 1);
db.useRepo<User>().Include(list, x => x.Orders);
// 或 RichRepo.Include / clip.include(list, …)
```

复用 `NavQueryGuide`：一对多二次 `IN`，禁止隐式笛卡尔。
